# LV-UE01 管理认证、上传与 Flash 识别离线审查

范围：从用户已导出的原始固件追踪代码。没有连接 AP、扫描网络、提交配置、上传固件、重启或进入 Bootloader。以下区分静态代码证据与尚未验证的运行条件；当前网页候选未加入底层安全补丁。

后续已另存 [认证第一阶段候选](auth-hardening/README.md)，修补默认账户短路及公开路径匹配，20组原生回归通过；原网页候选不覆盖。本报告以下保留原固件发现，上传前认证顺序仍未修复，不将第一阶段补丁视为全部风险已解决。

再后续另存 [第二阶段候选](preupload-hardening/README.md)，加入 POST 请求体处理前认证，20组认证和20组守卫回归通过。完整 HTTP 路径、输出/清理与真实擦写均未验证；以下风险描述仍适用于原固件和未修补网页基线，不能将第二阶段受限实验称为完整实机修复。

## 1. 默认账户组合会跳过常规认证

**已确认的静态逻辑，优先处理。**

`auth_check`（0x8000e4e0）先检查公开资源例外，然后调用 0x8000e398。后者读取 `SYS_USERS`（配置 ID 0x010b0200）和 `SYS_ADMPASS`（0x01010200），分别与字面量 `admin` 比较。用户名和密码都相同时返回 0；0x8000e568 跳转至成功返回路径，不继续校验请求凭据。否则进入常规 Basic 凭据解析、账户比较和失败 401 路径。

因此“后端有认证函数”不能推导出“所有情况下都要求认证”。这修正了此前对 POST 认证保护的笼统描述。当前设备是否还使用默认账户未重新读取；历史配置不能当作当前凭据证明。

可立即采取的运行配置措施是通过现有管理界面设置非默认、独有的管理员密码。但这只能避开默认账户短路条件，不能证明下面的上传路径已受保护。本轮没有替用户修改密码。

## 2. 公开资源使用子串匹配

**已确认的静态逻辑，具体绕过尚未验证。**

0x8000e424 对请求路径调用字符串子串搜索（0x8015cb50）。例外词为 `login`、`favicon`、`lang_`、`live`、`jquery`、`gl.js` 和 `fctest.htm`，不是逐个资源精确匹配。

需要进一步核对路径归一化、路由匹配及敏感命令分发的组合。不能只凭子串例外宣称已有可用绕过。0x8000ff58..0x8000ff70 在认证前已将查询字符串与路径分开，因此不能假设在普通查询参数添加例外词就会匹配。

源码级修复方向：对确需公开的资源使用精确、规范化路径白名单，所有配置、备份和升级入口统一认证；不再以默认密码组合放行。

## 3. 固件流式上传可能先产生 Flash 副作用，再进行常规认证

**重要的静态风险路径，未进行真机上传验证。**

可见调用链：

1. POST multipart 解析识别 `SYS_UPG`（0x80010498 → 0x80010e3c）。
2. 上传块在 0x80010598..0x800106b0 路径送入 0x80006614。
3. 该函数经过初始标记/尺寸等条件后，可调用擦除包装函数（0x800066ec → 0x80015268）及编程包装函数（0x80006724 → 0x80015660）。
4. 同一 HTTP 处理函数的常规认证调用位于后续 0x80010784 → 0x8000e4e0。

因此不能认为“上传最终返回登录页/401”就证明 Flash 没被操作。仍需确认全部状态和镜像头约束及其他入口条件，才能完整判定可达性；本轮不把静态路径说成已验证漏洞利用。

**不通过发送测试固件或空上传验证此问题。** 页面端的 CRC、文件名限制和确认框只约束该页面，程序调用可以直接绕过页面。下一步修复必须把认证放在解析/处理上传内容和 Flash 副作用之前，并验证失败请求不会调用擦写路径。更换管理员密码、SameSite Cookie 都不能替代该后端调整。

## 4. CSRF 保护尚未确认

原 HTTP 解析器识别并存储 Referer（0x80010924..0x80010938）。仅解析该字段不能证明在修改前验证来源。尚未完成服务端 Origin/Referer 校验或 token 校验的完整数据流分析。

新页面设置 Cookie 时使用 SameSite=Lax，但不代表原后端已获得完整防护，尤其不能覆盖历史 Cookie、同站请求或非浏览器调用。没有在真机执行跨站提交测试。

## 5. 运行时 Flash 几何参数不能直接当作物理容量

已定位运行时识别函数 0x80014b58，其中 0x80014c44 设置 JEDEC Read ID 命令 0x9f。读取结果与 11 个编译表项匹配，所选表项指针保存至 0x802131b8，初始化函数 0x80014d60 按擦除块大小 × 数量计算容量边界。

未精确匹配时存在备用项选择逻辑，初始备用项是 mx25l1605d，其编译几何参数为 65536 × 32 = 2097152 字节（2 MiB）。因此即使以后读到驱动报告 2 MiB，仍需结合实际 ID/丝印，确认并非备用表项。全部编译表项及区域大小见 management-flash-audit.json。

当前只有前 1 MiB 读取文件，没有实际 JEDEC ID，**本机物理 Flash 容量仍未知**。不能通过跨范围读取成功或重复数据推断芯片容量，也不执行试探性擦写。

## 6. 恢复入口代码存在，恢复能力尚未实测

Bootloader 导出含 U-Boot 1.1.3、`spi id` 帮助（Flash 0x1474b）及 TFTP 加载/写入菜单（0x13214）。这不证明串口针脚、电平、启动中断或 TFTP 恢复已可用。

运行中的 eCos CLI 已知 `spi` 帮助只有 rd/wr/er；不能在该环境直接套用 Bootloader 的 `spi id`。本轮不重启进入 Bootloader，也不猜测 UART 电平或恢复参数。
