# SSID 测试结果与恢复状态

> 后续管理地址测试已完成新的正常重启验证，当前状态见 [FINAL-TEST-CONFIG.md](FINAL-TEST-CONFIG.md)。下文为更早的 SSID 测试记录，旧管理入口及临时地址状态不代表最新结果。

## 最终状态

- BssidNum 已回读为 1；RadioOn=1、WlMode=1。
- 上游状态为 Connected（页面值 2）。
- Mac 有线接口 en10 已重新取得 192.168.1.11，链路为 100baseTX full-duplex。
- 强制通过 en10 请求 Apple 连通性检测页面，HTTP 200，实际本地源地址为 192.168.1.11，响应包含 Success。实际有线转发已验证恢复。
- 直连管理地址 192.168.10.1 可访问。原 192.168.1.2 在重配置过程中曾恢复可达，但最后一次检查未连接成功，不将其列为已稳定恢复的入口。
- 恢复用临时地址 192.168.10.2 仍保留，移除需要用户在 Mac 本机终端执行管理员命令：

```sh
sudo /sbin/ifconfig en10 inet 192.168.10.2 -alias
```

该命令仅移除指定临时地址，保留 DHCP 地址 192.168.1.11。工具侧 sudo 没有缓存授权，因此尚未完成移除。

## 正确格式的运行时测试

1. 确认初始 BssidNum=1。
2. 按网页原始表单格式提交 BssidNum=0。
3. 连续三次回读均为 BssidNum=0、RadioOn=1、WlMode=1，三次上游状态均为 2。
4. 使用相同格式提交 BssidNum=1，随后回读为 1，上游状态为 2。
5. 完成上述最终有线连通性验证。

原始事件见 `ssid-raw-test-events.json`。参数回读和上游连接状态证明运行时设置可修改，但没有独立的射频扫描证明扩展 BSSID 已停止发射，也没有在 0 状态下验证 DHCP 重获、完整有线转发或长期稳定性。故不能将该参数称为已验证的完整关闭方案。

## 冷启动观察与限制

在此前 BssidNum=0 的状态下，用户给 AP 断电重启后：直连 192.168.10.1 可访问，回读仍为 0；上游状态为 0，Mac 有线端获得 169.254.65.149。说明至少该次 0 状态启动未建立上游连接，不适合直接作为长期配置推荐。

这些结果提示运行时改值与冷启动初始化可能存在差异，但尚未完成严格控制变量的重复实验。X99 的原问题发生在日常配置下两台设备同时冷启动；此次 0 状态的异常不能证明与 X99 同源。

## 请求格式修正

最初测试和恢复使用 `--data-urlencode`，将 SET0 的内层等号编码，和原网页脚本拼接的格式不同；此前恢复请求没有产生经过验证的恢复结果。改为如下原始格式后，成功恢复并回读为 1：

```text
CMD=Wl_Basic&GO=wl_basic.htm&SET0=70648064=1
```

这次工作中的请求构造问题拖延了恢复。固件处理编码请求的具体失败机制尚未完全定位，因此不能把所有超时都归因于编码。正确格式的请求也出现过 HTTP 响应超时，但随后回读证明参数已生效；判断应以实际回读和连通性为准。

后续如再次测试，应先保留直连管理通道，使用与原网页一致的请求格式，并分别验证参数回读、射频状态、DHCP、实际转发和冷启动结果。
