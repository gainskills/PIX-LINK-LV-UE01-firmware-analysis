# 长期运行测试配置：已完成正常重启验证

> 后续隐藏 SSID 已通过配置导入成功设置，用户扫描确认看不到 `_Ext`，正常重启后也回读为 `1;0;0;0`；WPS 仍关闭。临时本地恢复地址已再次清除，最后一轮正常重启的已保存回读文件也确认 LAN_IP=0.0.0.0、DHCP=0、上游管理 8080 保留。用户已接回 X99 并通过 Wi-Fi 管理；X99/mDNS 的长期复测由用户进行，助手停止相关探测。新增网页/依赖变更仅为离线候选，见 `../web-update/README.md`，尚未刷入 AP。

当前管理入口：**http://192.168.1.2:8080/**。该 IP 来自上游 DHCP，未来地址以路由器租约为准。

## 实际配置

| 项目 | 配置 |
| --- | --- |
| 中继模式 | SYS_WLMODE=1 |
| LAN 静态管理地址 | LAN_IP=0.0.0.0，不再使用 192.168.10.1 |
| LAN 地址模式 | LAN_IP_MODE=1，保留静态模式，不启用隐藏的 LAN DHCP 客户端路径 |
| 本机 DHCP 服务器 | LAN_DHCPD_EN=0 |
| 上游接口管理 | SYS_RM_EN=1，SYS_RM_PORT=8080 |
| 上游管理来源配置 | SYS_RM_IP=0.0.0.0，未设置单一来源 IP 限制 |
| 扩展 BSS / 无线上游 | BssidNum=1、ApCliEnable=1，保留原无线配置 |
| 扩展 SSID 隐藏 | WLN_HideSSID=1;0;0;0，用户扫描确认 |
| WPS | WLN_WscConfMode=0，重启后保持 |

这份固件把上游接口称为 WAN。开启其管理监听后，管理页面能通过现有上游 DHCP 地址访问；这是实测可行的入口。没有刷写固件。

## 已完成验证

1. 原始配置导入后，所有导出键值与原始备份一致，恢复入口 192.168.10.1 可用，有线转发正常。
2. 保留旧地址时，先单独启用上游管理监听，确认 192.168.1.2:8080 可以导出配置。
3. 再将 LAN_IP 改为 0.0.0.0。提交响应曾超时，但随后从上游管理入口回读确认设置生效，不以超时判定失败或重复写入。
4. 通过原网页的 SYS_CONF / CCMD=0 执行正常重启。恢复后，192.168.1.2:8080 配置导出 HTTP 200；回读确认上述关键设置保留。
5. 重启后，强制经 Mac en10 获取 Apple 连通性检测页面，HTTP 200、包含 Success，实际源地址 192.168.1.11。192.168.10.1 HTTP 请求超时。
6. 重启期间抓包看到上游 192.168.1.1 向 AP 提供 192.168.1.2，向 Mac 提供 192.168.1.11；捕获到的相关 OFFER/ACK/NAK 均来自 192.168.1.1，没有观察到 AP 本机服务器向这两个客户端提供租约。该有限时间窗口不替代长期检查。

配置及证据见 `longrun/verified-reboot-profile.bin`、`longrun/verified-reboot.pcap`、`longrun/verified-reboot-summary.json`、`longrun/events.json`。配置含密钥，文件权限设为 0600，不应公开。

## 边界与长期测试

- 没有验证 X99 同时冷启动场景；本轮最终验证是网页正常重启，不能当成断电冷启动测试。
- 未测得资源占用或稳定性改善，不宣称节省了多少内存、CPU 或已修复 AirPlay。
- 抓包仍看到 Mac 在恢复时先收到上游 DHCP NAK，随后重新 DISCOVER 并取得正确 ACK。由于服务器为上游，不能将这一 NAK 归因于 AP 本机 DHCP 服务器；具体触发原因仍未定位。
- LAN 命令还自动将已停用 DHCP 地址池配置改为 0.0.0.100–0.0.0.200。服务器保持关闭，本轮没有重新启用它。所有无线配置与原始备份一致。
- Mac 目前仍保留 192.168.10.2 临时别名；它不会开启 AP 服务器。可在本机用 `sudo /sbin/ifconfig en10 inet 192.168.10.2 -alias` 移除，保留 192.168.1.11 DHCP 地址。
- 接回 X99 后记录实际地址/掩码/网关、AirPlay 中断时间、是否自行恢复，以及两台设备同时断电启动的结果。保持其他参数不变，以便解释结果。

## 恢复材料

原始备份为 `longrun/before-profile.bin`，恢复原静态 192.168.10.1、DHCP 服务器关闭和原中继设置。若当前管理入口可用，可通过 SYS_CONF / CCMD=3 的 multipart 导入恢复，文件字段为 files。导入后必须重新回读确认，不以 HTTP 200 单独判定恢复成功。

## 被替代的尝试

早先 LAN_IP_MODE=0 的隐藏 DHCP 客户端模式导致两个管理入口均不可用，用户断电重启后仍不能管理；没有继续使用。原先依据 HTTP bind(INADDR_ANY) 推测所有本地接口都可管理是不充分的：服务启动还有网络接口地址检查，且固件单独控制上游管理监听。本轮通过先验证上游监听、再停用旧地址解决了实际管理入口问题；隐藏客户端模式的内部故障根因仍未完全确认。
