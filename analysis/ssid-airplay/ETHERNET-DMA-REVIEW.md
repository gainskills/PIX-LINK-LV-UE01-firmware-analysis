# 以太网 RX 队列与 TX 回收离线复核

范围：本机原 main 的接收处理 `0x800173f4` 和中断/发送回收 `0x800177fc`。没有访问 AP、收发测试流量、修改寄存器、配置或固件。全部描述符、接口、缓冲和硬件状态均为合成输入，不代表故障现场状态。

## 接收：六组原代码实验

[emulate_rx_ring.py](../../logic/ssid-airplay/emulate_rx_ring.py) 执行原接收函数，缓冲分配后端在相关场景中使用返回 0 的替身。模型不进入成功收包后的上层交付和缓存维护。

| 输入场景 | 观察到的处理 |
| --- | --- |
| 没有已完成描述符 | 保持队列位置，返回 |
| 小于 60 字节的帧 | 增加 context+0x1c 计数，交还描述符并推进索引 |
| 在队列末尾丢弃短帧 | 索引正确回绕到 0 |
| 整圈四个短帧全部就绪 | 处理四个后有界退出，索引回到 0 |
| VLAN 帧没有匹配接口 | 增加 context+0x20 计数，交还描述符并推进索引 |
| VLAN 接口匹配但补充缓冲分配失败 | 增加 context+0x24 计数，保留旧缓冲，交还描述符并推进索引 |

处理后的描述符控制字均为 `0x40000000`，模型中的 RX_CALC 写入与已处理描述符序号一致。每组验证原函数返回及栈平衡。证据：[rx-ring-experiment.json](rx-ring-experiment.json)。

这说明这些特定丢弃/分配失败分支并非无条件停止 RX 队列。不证明其他缓冲分配、成功交付、DMA 缓存一致性或中断时序没有问题。

## 发送：五组原代码实验

[emulate_tx_reclaim.py](../../logic/ssid-airplay/emulate_tx_reclaim.py) 执行原中断处理/发送回收函数，仅提供 TX 状态，不进入 RX 中断。通用缓冲释放后端是替身，不执行实际分配器内部。

| 输入场景 | 观察到的处理 |
| --- | --- |
| 无 TX 完成中断位 | 不回收，即使模型描述符已完成 |
| 有中断但 DMA 尚未完成描述符 | 保留描述符和缓冲，不推进回收索引 |
| 完成描述符、无接口关联 | 缓冲加入适配器空闲链表，清除关联元数据，增加空闲描述符数 |
| 完成描述符、有接口关联 | 更新接口计数并调用释放后端，清除关联元数据，增加空闲描述符数 |
| 整圈四个描述符完成 | 回收四项，空闲数变为 4，尾索引回绕到 0，返回链表有界 |

原处理还确认/清除读取到的中断状态，结束时写回适配器保存的中断使能掩码。MMIO 仅为内存模型，记录这些写入不等于仿真真实中断控制器。证据：[tx-reclaim-experiment.json](tx-reclaim-experiment.json)。

模型曾在释放后端拦截时失去栈平衡：追踪发现入口 `0x80121528` 的首条 `addiu sp,sp,-0x28` 仍在模拟器停止时生效。最终将后端明确建模，恢复其入口 SP 后再继续原调用者，五组均通过。此问题属于模拟边界，不是设备故障证据；不能把释放函数内部列入已验证范围。

## 诊断含义

目前没有证据支持把上述局部错误分支直接修补为掉线修复。发送回收依赖中断位及描述符完成位，但本实验没有模拟丢中断、真实 DMA 停滞或完整重启恢复，不能宣称已排除它们。

已观测的物理 link down 与 link up 时仍不通需要分别保留：DMA/转发问题可以作为后者的候选方向，却不足以解释物理链路确实熄灭的全部情况。下一项有区分力的实机证据应是同一故障窗口的物理状态与 DMA 索引变化，而非再根据 DHCP、播放状态或单个累计计数猜测。
