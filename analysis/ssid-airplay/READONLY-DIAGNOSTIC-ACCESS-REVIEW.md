# 原固件只读诊断入口补充核查

本轮只分析本地原固件，没有访问 AP、发送命令、修改配置或固件。

## show memdump 没有实际转储实现

原 main 文件偏移 `0x1ef5b0` 的表项将字符串 `memdump`（地址 `0x801718b8`）关联到处理函数 `0x80079f50`。

完整处理函数 `0x80079f50..0x80079f98`：参数非空时调用数值解析函数 `0x800fe9ac`，进制 16；随后直接将返回值设为 1 并返回。它没有使用解析出的地址，也没有读取或打印该地址内容。参数为空时先调用一次提示 printf，随后仍走解析与返回路径。见 [原指令](memdump-handler-disassembly.txt)。

三组离线处理函数实验分别提供地址字符串 `8025e740`、`0` 和空指针。数值解析和 printf 使用明确的替身，原处理函数执行后均返回 1；没有读取所请求的 RAM 地址，没有栈之外的写入。见 [结果](memdump-entry-experiment.json) 和 [实验脚本](../../logic/ssid-airplay/check_memdump_entry.py)。没有映射 MMIO，访问硬件寄存器会导致实验失败。

曾尝试同时执行原数值解析函数，本地 Unicorn 在其跳转处发生 CPU 异常，故最终实验限定为处理函数、解析使用替身。该异常不来自设备，不作为固件崩溃证据。实验直接调用处理函数，不代表已实测完整 iwpriv 分发。

## 对故障诊断的影响

`reg` 命令只能映射 MMIO，不能读 RAM；这个 `memdump` 表项也不能补齐 RAM 查询能力。因此目前不能通过这两个原固件入口取得内部重连计数、运行时查询接口或 PHY BMCR/BMSR。不能根据命令名存在就宣称已具备内存/PHY 诊断能力。

已取得的端口状态、硬件 link 事件和无线统计仍有效，但不足以区分所有掉线原因。本轮没有证明其他所有未记录入口均不可用，也没有找到新的可用只读入口。诊断镜像虽通过离线校验，实际启动与可控恢复仍未验证，不能把它描述为可安全部署的修复。
