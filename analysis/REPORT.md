# AP 固件导出与逆向初步报告

## 后续更新：完整备份

2026-10-20 已完成标称 2 MiB 地址窗口的双份只读备份，并通过独立逐块/整份校验；原固件 uImage CRC 和 SHA256 与本报告导出一致。运行时 JEDEC ID 和恢复仍未测试。详见 [备份结果](recovery/README.md)。以下为首次 1 MiB 导出的历史记录，原文件及其元数据未改写。

## 结论

已经通过设备 Telnet 调试接口导出 Flash 的前 1 MiB，并提取、校验和解压主程序。固件可以继续离线逆向，不需要先利用漏洞或刷入其他固件。

此次仅登录并运行帮助、进入 OS 菜单和 `spi rd` 读取命令，没有执行 Flash 写入、擦除、配置修改或重启命令。

## 文件

- `flash.bin`：前 1,048,576 字节的 Flash 读取结果，包含启动区、其他前置区段和程序容器。
- `uimage.bin`：从 0x50000 提取的程序容器，包括 64 字节头部。
- `uimage-payload.bin`：通过 CRC 校验的原始程序载荷，包括内部解压器。
- `main-decompressed.bin`：解压后的主程序。
- `main-analysis.elf`：为分析人工封装的 ELF32 MIPS 小端文件，入口 0x80000400。可导入 Ghidra；这不是设备原生 ELF，也不是刷机文件。封装未恢复 BSS、函数边界或完整符号表。
- `main-strings.txt`：主程序可打印字符串及文件偏移。
- `embedded-web/`：提取的 14 个 HTML 模板及偏移清单；编号文件名不代表已恢复原始网页路径。
- `web-command-handlers.json`：从固件中的命令分发表读取的处理函数地址。
- `*-disassembly.txt`：启动程序、加载器、主程序开头和部分 Web 处理代码的反汇编。
- `metadata.json`、`SHA256SUMS`：容器信息和文件哈希。
- `flash-read.log`、`flash-repair-0.log`：读取和复读的原始控制台输出。
- Python 脚本是此次读取和分析的工作记录，含固定临时路径及会话假设；复用前需要调整。反汇编脚本依赖 Capstone。

## 已定位的逆向入口

主程序保留了较多函数名和错误字符串，可用于定位驱动、Telnet 调试和 Web 处理逻辑。以下地址来自实际命令分发表：

| 入口 | 主程序地址 |
|---|---|
| SYS_UPG，升级处理 | 0x8000B6E4 |
| SYS_CONF，配置处理 | 0x8000D6BC |
| SYS_PASS，密码处理 | 0x8000CBE0 |
| /profile.bin，资源处理函数 | 0x8000B640 |

这些地址表示进一步分析的起点，不代表已经证明存在漏洞，也不代表 profile.bin 能导出完整固件。

## 可靠性和范围

长段控制台输出偶尔混入额外字符，出现 9 位十六进制词；简单截断会产生错误数据。因此在完整读取后，对 420 个可疑的 16 字节区段进行了重读，并由独立的 uImage 载荷 CRC 验证修正后的程序内容。LZMA 也成功完整解压。

程序容器头部和载荷均已通过 CRC 验证。启动区和其他前置区段没有同等的独立整区校验，不能将程序载荷的校验结论扩大到整个 Flash。本次读取范围为前 1 MiB，未通过芯片 ID 确认物理 Flash 总容量；也没有测试恢复或刷写。

原始 Flash 和日志应按设备备份保管，可能包含配置、无线凭据和校准数据，不宜直接公开发布。
