## 诊断内容

新增 CLI 命令 `reg phy`。这是候选固件中的设备 CLI 命令，当前运行的原固件不支持，不是在电脑终端直接执行的命令。

输出先显示 `relink_calls` 和 `last_cp0_count`，随后顺序读取固定 PHY 0 的寄存器：

| 顺序 | 寄存器 | 用途 |
|---|---|---|
| 1 | 0 / BMCR | 控制状态 |
| 2 | 1 / BMSR | 第一次读，保留锁存状态 |
| 3 | 1 / BMSR | 第二次读，查看当前状态 |
| 4 | 4 / ANAR | 本端协商通告 |
| 5 | 5 / ANLPAR | 对端协商能力 |
| 6 | 6 / ANER | 协商扩展状态 |

例如 `PHYDIAG p0 reg=1 result=30765 hex=782d`。同一寄存器的两行按读取顺序保留，不丢弃第一次结果。BMSR 读取可能清除锁存位，因此查询本身会影响后续读到的历史状态。

读取返回原始 16 位数；负数代表失败：`-1` 参数无效、`-2` 控制器忙、`-3` 轮询超时。遇到失败即停止剩余读取。每次事务保存/恢复 CP0 Status 和 GPIO 引脚模式，只发 MDIO read 命令；轮询上限为 65,536 次，墙钟时间尚未标定。格式化输出在临界区退出后进行。没有自动轮询。

`relink_calls` 只记录进入已定位的 `0x80017134` 主动 PHY down/up 函数的次数，保留原函数行为。它不覆盖所有可能的复位、初始化或掉链原因。`last_cp0_count` 是最后一次进入时的原始 CP0 Count，频率未标定且会回绕，不能直接作为秒数。两者重启清零，计数按 32 位回绕。输出是查询起始时的计数快照，各 PHY 读取不构成同步快照。

因此，未来在实机上若故障前后计数增加，可进一步关联固件主动重连；计数未变，也只能说明这一个函数没有新增调用，不能排除其他驱动/硬件路径。

## 修改范围

以既有网页候选的 main 为基线，独立生成文件；原网页候选不重写。整个镜像继承新网页、WPS 出厂默认关闭、图片移除和 HTTP 回调变化。以下三个范围只描述相对网页候选的诊断增量，末端不包含：

- `0x19ecc4..0x19efd0`：780 字节代码/字符串/初始计数，位于已退役且为零的图片区域；680 字节为代码。
- `0x16d34..0x16d3c`：主动 relink 入口跳转，保留并重放原先两条指令。
- `0x211ff0..0x211ff4`：`reg` callback 指针；除精确的 `reg phy` 外，所有参数原样转交原处理函数。

诊断增量没有修改原生 PHY 初始化、协商或 EEE，也不会主动更改已保存配置；整个组合镜像仍包含上述网页和出厂默认值变化。新页面的保存操作还可能提交模式、带宽、功率、DHCP 等字段，因此不能把整个镜像当作相对原固件的纯诊断对照。本补丁不升级驱动或内核。

## 已验证与边界

10 项测试通过，覆盖实际 MIPS 机器码的读取成功/忙/超时/越界、两次 BMSR 不同结果的保留、失败中止、旧命令分发、调用约定、主动重连计数和原入口指令重放，以及已封装镜像范围/CRC/压缩回读。测试模拟 MMIO、printf 和 CP0 Count 的采样值，不是硬件测试。

独立制品校验确认：已知基线 SHA、原网页候选未改、main/容器长度与 loader 不变、CRC 正确、LZMA 回读一致、相对网页基线仅三个许可范围改变、callback/跳转/CP0 Count 指令正确、Capstone 完整解码全部代码。独立代码审查未发现具体缺陷，详见 `CODE-REVIEW.md`。

尚未验证：实际代码区域执行/缓存和启动行为、真实 MDIO 的忙位清除和完成标志刷新、引脚时序、硬件并发、超时后控制器恢复。读取采用原生驱动同类事务，但模拟器不能证明这些假设。没有修复或排除 X99 故障根因。

后续已完成标称 2 MiB 地址窗口的双份备份并通过独立校验，见 [备份结果](../recovery/README.md)。实际 JEDEC ID、恢复入口和 RAM 试启动仍未验证；备份成功不代表候选可启动。当前文件继续保留 NOT-FOR-FLASHING 标识。

## 离线复现

Python 3；测试依赖 `unicorn==2.1.4`，反汇编依赖 `capstone==5.0.7`，封装仅使用标准库。脚本兼容本机现有 `/private/tmp` 依赖目录，也可在安装上述版本的独立 Python 环境运行。

从项目根目录执行：

```sh
python3 firmware-analysis/ap-192.168.1.2/phy-diagnostic/test_patch.py
python3 firmware-analysis/ap-192.168.1.2/phy-diagnostic/builder.py
python3 firmware-analysis/ap-192.168.1.2/phy-diagnostic/verify.py
```

本机沙箱阻止 Unicorn JIT 时进程退出 132；经过批准在沙箱外运行测试可通过。这不涉及网络权限或设备连接。

制品：`main-phy-diagnostic.NOT-FOR-FLASHING.bin`、`phy-diagnostic.uimage.NOT-FOR-FLASHING.bin`、`payload.bin`。证据：`build-manifest.json`、`test-results.json`、`verification-results.json`、`payload-disassembly.txt`。生成器拒绝未知源文件 SHA，不会静默适配其他版本。
