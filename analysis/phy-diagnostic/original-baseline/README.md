# 原固件基线 PHY 诊断候选

**PHY 诊断实验固件，不是 X99 掉线修复。** 2026-10-22 用户授权后，首版 64421c4f… 已启动、配置保留、X99 HTTP 200，但 Telnet 内置 reg 绕过命令表，诊断查询未生效。现已新增真实分发路径的回归测试并修正直接调用，完整22项测试通过。首版制品保存在 installed-v1-64421c4f/；当前修正版为 ae986324…，实机验收以[部署记录](../../deployment/README.md)为准。文件名保留实验标签，硬件恢复仍未验证。

## 用途与修改范围

用于后续有恢复保障的故障取证：保留原固件页面、脚本、默认配置、原生 PHY 初始化和网络处理，仅将 favicon 响应置空并借用其存储加入既有诊断。原厂 WPS 默认值也保留，不能将此候选当成此前默认关闭 WPS 的网页更新版本；当前实机保存的 WPS 状态不由本次离线检查确认。

| main 文件范围（右端不包含） | 用途 |
| --- | --- |
| 0xa4b0..0xa4b4 | favicon 响应长度设为 0，避免返回诊断指令 |
| 0x16d34..0x16d3c | 主动 PHY 重连入口计数跳转，保留原行为 |
| 0x11207c..0x112080 | Telnet 内置 reg 直接调用转到诊断分发，延迟槽不变 |
| 0x19ecc2..0x19f140 | 1,150 字节 favicon 分配区，内含 780 字节诊断及初始化数据 |
| 0x211ff0..0x211ff4 | reg CLI 回调；精确 reg phy 外仍转交原处理函数 |

相对原 main 共改变 1,067 字节；其他每一字节一致。诊断代码保持原有版本：查询固定 PHY 0 的 BMCR、两次 BMSR、ANAR、ANLPAR、ANER，并显示已定位重连函数的调用计数和原始 CP0 Count。读取有忙检查、有限轮询、引脚/中断状态恢复；失败后停止后续读取。BMSR 查询可能清锁存位，计数也只覆盖这一个函数。详细语义见 [父目录诊断说明](../README.md)。当前运行原固件不支持 reg phy，不能把候选命令当作现有设备能力。

## 验证与审查

完整诊断测试当前 22 项全部通过，新增从真实 Telnet 内置 reg 调用点执行并返回的测试；该测试在修正前失败、修正后通过。包括现有 MIPS 负载测试、从完整原基线 main 执行入口/查询、实际 favicon 回调的零长度响应、容器/loader/CRC/LZMA 回读、超预算拒绝、未知输入拒绝，以及独立验证器对截断、压缩损坏、伪造清单且重算 CRC 的默认值篡改拒绝。

独立审查发现并修复一个构建保护问题：选定原固件或网页基线时，输入必须与选定基线的指纹匹配，不能只因为属于另一个已知输入就接受并错误标注。两种源文件互换均由回归测试验证。审查者还独立核对当前二进制、差异范围及独立验证器，修复后无阻塞发现。

独立验证不调用构建器：固定原始来源和隔离 main/负载指纹，检查五个许可范围、未修改 loader 和非 CRC 头字段、头部/载荷 CRC、带长度上限的解压、实际流尾与 FF 填充、CLI/跳转/CP0 指令、计数初值及完整代码反汇编。

## 离线复现

```sh
python3 firmware-analysis/ap-192.168.1.2/phy-diagnostic/builder.py --baseline original
python3 firmware-analysis/ap-192.168.1.2/phy-diagnostic/verify_original.py
python3 -m unittest discover -s firmware-analysis/ap-192.168.1.2/phy-diagnostic -p 'test_*.py' -v
```

命令均不访问设备。仿真测试在本机需沙箱外初始化 Unicorn，不涉及真实网络、UART 或 MMIO。原网页组合版本仍由不带参数的 builder.py 生成，输出不覆盖本目录。

## 实机限制

未验证资源区代码执行/缓存、真实 MDIO 忙/完成时序、超时后控制器恢复、候选启动或恢复。双份 2 MiB 备份已独立校验，但实际 JEDEC ID 和恢复未测试。U-Boot GPIO 升级会写入/擦除；RAM 菜单自动启动也可能保存环境，网络菜单控制尚无已验证入口，见 [恢复准备](../../recovery/README.md)。因此仍保留 NOT-FOR-FLASHING，暂不刷入或触发升级。

## 原生 loader 补充验证

新增三组离线原生自解压实验：原版对照和本候选均到达 main 入口 0x80000400，展开结果与各自预期 main 逐字节一致；无效 LZMA 属性进入失败分支。执行镜像内原 MIPS loader/decoder，不使用 Python 解压填充模拟 RAM；没有执行 main 初始化或访问设备。候选哈希不变，原有 21 项测试与这三组实验分别记录。详见 [原生 loader 复核](NATIVE-LOADER-REVIEW.md) 和 [准备状态](../FIRMWARE-PREPARATION.md)。

## 早期启动放置补充验证

另有三组早期 main 实验，原版/候选均到达构造函数入口，原生 BSS 清零未覆盖四个诊断范围；放在 BSS 内的合成哨兵则被清除。板级初始化仅在模拟 RAM 中使用返回替身，没有执行构造函数、外设或完整系统启动，候选文件未改。详见 [早期启动复核](EARLY-STARTUP-REVIEW.md)。

## 构造前段补充验证

后续缩小了模拟替身范围，保留软件向量初始化。原版/候选两组均完成前 8 个构造、进入第 9 个，在系统控制寄存器写入前停止；诊断区没有写入且内容保留。完整构造对照因遇到不支持的硬件操作仍为 INCOMPLETE，不算完整启动通过。见 [构造阶段复核](CONSTRUCTOR-REVIEW.md)。

## 输出验收补充验证

八组候选回调/负载实验覆盖两次 BMSR、全零有效结果、初始忙、超时、中途失败及计数上限/回绕。明确保留部分结果和负数八位 hex，避免后续记录误判。仅为离线模型输出，未新增现场工具或执行实机查询，候选文件不变。见 [输出验收规则](OUTPUT-ACCEPTANCE.md)。
